## Prerequisites

Confirm three things before drafting:

1. **A selected concept.** The user picked one of the Ideas stage concepts, described their own, or asked to combine or modify them. If there is none, ask which one to develop, then stop.
2. **Company, audience, and platform.** These carry over from the ideas stage. If any are missing, ask for only those, in one short message, then stop.
3. **Source material.** Always ask before drafting, even if the concept seems clear. Ask in one short message: "To make this land, can you share any of these? A call recording or transcript, a link to a relevant page, product docs, internal notes, or data. Even a few sentences about what you've seen firsthand helps." If the user already supplied material in the conversation, skip the ask and name the material you will use. If they give a link, open and read it before drafting.

## If the user has no material

Push back once. Be concise: name what is missing and why this concept depends on it. Accept any relevant alternative the user offers.

If the user still has nothing, do not invent. Offer one of:

- A clearly labeled skeleton with `[PLACEHOLDER: description of what goes here]` markers.
- A different concept that the available material can support.

## Rules

The draft must:

- Preserve the selected concept's central argument.
- Use concrete details from the supplied material, and nothing the material does not support.
- Contain no fabricated first-person experience. If the user did not describe an experience, the post cannot claim one. Do not write "we saw," "I spent a week," or "a customer told us" without a source.
- Match the client's voice and the platform's conventions.
- Read naturally aloud.

### Sentence-level source check

Before showing a draft, tag every sentence as sourced, opinion, or unsupported. Cut or reframe every unsupported sentence. General claims about how an audience thinks or behaves are unsupported unless the source says so. The claims-to-verify list must cover these sentences, not only numbers and product facts. (Full text in `guardrails.md`.)

### Attribution and secondhand claims, security/compliance/performance claims, using sources

See `guardrails.md`. These apply unchanged to drafts.

### Human test

Before showing a draft, ask whether a named person at the company could publish it under their own name without editing. Fix any of these:

- A hook that could open a post about any company.
- Sentences that are all the same length or rhythm.
- A closing line that restates the post.
- Stacked abstract nouns ("alignment," "enablement," "synergy") instead of what actually happens.
- Words nobody says out loud.
- More than one em dash per post.

### Platform rules

- **LinkedIn:** The first two lines must carry a specific claim, since that is all readers see before "see more." Do not default to numbered lists, one-line paragraphs, or a closing question. Use length only when the material justifies it.
- **X:** A standalone post must be 280 characters or fewer. Count the characters, revise if over, and state the character count of every X post. For a thread, each post must stand on its own. Do not pad.
